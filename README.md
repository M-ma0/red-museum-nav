# 红色博物馆 · 云上观展导航页

一个**纯静态**的导航页网站：把《红色博物馆线上入口与公众号菜单配置表》里的线上入口，
按"党史时序 / 场馆 / 入口类型"三种维度整理成可视化卡片墙，每张卡片配真实页面预览图，
点一下即可进入展厅。（源表 46 条，其中 6 条经巡检确认无法访问已删除，当前展示 40 条）

- 站点入口：`index.html`（双击即可打开，无需服务器）
- 数据来源：配置表「线上入口清单」46 条（其中 6 条经确认无法访问、已删除，实际展示 40 条）
  + 「聚合页 P1 结构」21 条 + 「公众号菜单配置」15 条
- 覆盖范围：15 家场馆 · 9 类入口（720°全景 / 3D数字馆 / 官网虚拟展厅 / 语音导览 / 沉浸式VR / 公众号 / 小程序）

## 一、目录结构

```
red-museum-nav/
├─ index.html                 站点入口（直接双击打开即可）
├─ 预览.bat                    一键本地预览（自动起服务并打开浏览器）
├─ assets/
│  ├─ styles.css              设计令牌 + 全部样式（庄重红博风）
│  ├─ app.js                  交互：搜索 / 多维筛选 / 弹窗 / 埋点
│  └─ qr.js                   迷你 QR 编码器（本地生成二维码，无外部请求）
├─ data/
│  ├─ entries.json            规范化后的站点数据（唯一数据源，含 40 条）
│  ├─ entries.js              由 entries.json 生成的内联数据（保证 file:// 可用）
│  ├─ placeholders.js         图片模糊占位（内联 base64，避免 31 次额外请求）
│  └─ dropped.json            已删除的无法访问入口留档（可据此恢复）
├─ images/thumbs/             卡片预览图（800×500）与 2 倍图（1600×1000）
├─ tools/                     构建脚本（维护时才需要）
│  ├─ build_data.py           xlsx → data/entries.json + 截图清单
│  ├─ shot-worker.mjs         Chrome 无头截图采集器（并发分片）
│  ├─ build_site.py           图片压缩（多档+模糊占位）+ 链接巡检 + 生成数据 + QA 报告
│  ├─ qa-site.mjs             站点自检（资源/数据/渲染/交互/移动端）
│  └─ serve.mjs               本地静态预览服务
└─ _build/                    构建中间产物（原始截图、日志、QA 报告，可删除）
```

## 三、功能清单

### 浏览与检索
- **关键词搜索**（在顶栏右上，`/` 快捷键聚焦）：匹配馆名、属地、展览名称、入口类型、分组与链接
- **可折叠的多维筛选**：筛选栏默认只占一行（含"筛选"按钮与已选条件摘要），点击才展开
  类型 / 场馆 / 属地三个维度；摘要上的 `×` 可单独移除某个条件
- **筛选结果优先**：一旦有筛选条件，精选推荐与云上观展合辑自动让位，
  结果区被自动滚动到视野内；清空条件后两块内容自动恢复。
  移动端应用筛选后筛选栏还会自动收起，把屏幕留给结果
- **云上观展合辑**：把"想怎么看"提前成一次点击 —— 全景漫游 / 数字专题 / 语音讲解 / 官方展厅，
  每张卡显示入口数量，点一下即套用对应筛选
- **三种浏览方式**：⭐精选推荐（官方确认 + 移动端最佳）、按党史时序分组、
  按场馆分组；一键在"时序 / 场馆"之间切换
- **引导型入口专区**：公众号、小程序、线下 VR 大空间等 7 个无法外链的入口单独成区，
  提供"查看操作路径"与"复制内容"

### 版面
- **一条红幕**：顶栏、首屏、页脚共用同一块深红底（极细斜纹 + 颗粒质感 + 烫金分隔），
  首屏只有标题与说明，字直接铺在红面上；内容区用暖纸底衬托卡片，不会满屏红底压住预览图
- 顶栏吸顶高度由脚本实测后写进 `--topbar-h`（窄屏搜索框换行后仍对齐），
  筛选栏吸顶偏移与锚点滚动都跟着这个变量走；滚过红幕后顶栏才出现投影，避免红面之间留接缝
- 顶栏一行放品牌 + 分组导航 + 搜索：宽度不够时导航收紧、再不够就横向滑动（右缘渐隐提示）

### 每张卡片
- 真实页面预览图（懒加载、16:10、鼠标悬停轻微放大）
- 左上角：入口类型浮标；右上角：来源与协议浮标（官方确认 / http）。
  40 条入口均已逐条打开核验、可正常观看，不再标注"待复核"；巡检发现的新失效链接才会另行标出
- 馆名 + 属地 + 展览名称 + 原表格的"移动端适配建议"（其中"需复核"按核验结果显示为"可正常打开"）
- 「立即观展 ↗」操作按钮，整卡可点，键盘可聚焦

### 体验与安全细节
- **http 链接**：微信内置浏览器会拦截 `http://`，点击时先弹二次确认，
  提供「复制链接」与「扫码在手机打开」，不会静默失败
- **特殊域名**（`.mil.cn`）：点击前提示域名来源，避免 iOS 微信风险提示造成困惑
- **失效链接已删除**：巡检确认打不开的 6 条入口已直接从数据中删除，导航页不再出现；
  源表原始数据与删除留档均保留，可随时恢复（详见下文「无法访问的入口已直接删除」）
- **UTM 埋点**：每个外链自动附加 `utm_source=cnyh_nav&utm_medium=...&utm_content=<入口ID>_<馆名>`，
  便于在馆方后台统计各入口点击量（对应原检查清单第 8 条）
- **弱网优化**：首屏只有约 135 KB（HTML+CSS+JS+数据，未压缩、不含图）。预览图做了三件事：
  1. 单张卡片图压到 **560×350 / 约 32 KB**（原 800×500 / 66 KB），另存 840×525 供高密度屏
  2. 用 `srcset` 双档 + `sizes` 让浏览器按屏宽与像素密度自动选源
     （桌面取 560w 得 1.9x，手机取 840w 得高密度清晰），不会过取
  3. 每张图配 **内联 base64 模糊占位**（约 400 B/张，随 HTML 一起到达），
     真实图片下载完成后淡入，慢网下不会出现大片空白灰块
- **懒加载**：`loading="lazy"` + 首屏首图 `fetchpriority="high"`，滚动到哪加载到哪
- **微信环境适配**：安全区适配、点击区域加大、`-webkit-tap-highlight` 友好、移动端两列栅格

## 四、部署到公众号（JS 安全域名目录）

1. 把整个 `red-museum-nav` 目录（可删掉 `tools/`、`_build/`）上传到自有服务器，
   例如放到 `https://<自有域名>/nav/`。
2. 公众号后台 → 设置与开发 → 公众号设置 → 功能设置 → **JS接口安全域名**，
   填入 `<自有域名>`，并把校验文件放到域名根目录。
3. 公众号自定义菜单 → 选择「跳转网页」→ 填入 `https://<自有域名>/nav/index.html`。
   （原配置表把「全部入口」指向 `/all/index.html`，如需保持一致，
   直接把本目录内容放到该路径，或加一条 301 跳转。）
4. 本站**不依赖任何后端接口**，也**不请求任何外部 CDN**，全部资源同源加载，
   不需要额外配置 CORS 或 CSP。

> 提示：全景类展馆流量较大，建议在页面上保留"Wi-Fi 环境下打开"的提示（页脚已含）。

## 五、如何维护数据

只改表格、不改代码是可行的，推荐流程：

```powershell
# 1) 用表格重新生成数据（会覆盖 data/entries.json）
python tools/build_data.py

# 2) 若新增了入口，采集其预览图（已存在的会自动跳过）
node tools/shot-worker.mjs _build/shots.json "_build/raw,images/thumbs" 0 1

# 3) 压缩图片 + 重新巡检链接 + 生成 entries.js
python tools/build_site.py
```

- 直接编辑 `data/entries.json` 也可，字段含义见下表；改完务必重跑第 3 步，
  否则 `entries.js`（页面实际加载的数据）不会更新。
- `tools/build_data.py` 中的 `URL_OVERRIDE` 可指定某些入口用哪个地址截图。

### 预览图是怎么来的

预览图全部由 `tools/shot-worker.mjs` 用**本机 Chrome 无头模式实地截图**（1280×800），
再经 `tools/build_site.py` 统一裁成 16:10、压成 800×500 与 1600×1000 两档。
采集器内置了这些针对性处理：

| 情况 | 处理 |
|---|---|
| 防盗链站点返回 403（如 `vr.fumenhu.cn`） | 自动补 `Referer` 请求头 |
| `.mil.cn` 证书链异常 | 启动参数放行证书错误 |
| 首屏有"进入网站"引导浮层 | 识别并自动点掉，再等页面渲染 |
| 全景站（720yun / 3D 数字馆） | 等 WebGL `canvas` 出现并留足渲染时间 |
| 页面长期无响应 | 单条目 150 秒硬上限，失败后重试一次 |
| 拿到的是 403 / 404 错误页 | 按体积与页面文案识别，**不写入**图片，改用品牌占位图 |

当前 33 个可跳转入口中 **31 个采到真实截图**，2 个（`bnz.jb.mil.cn` 等同域名的可达页面）?
采不到图但链接实测可达，降级为 CSS 品牌占位图。
**页面不会出现破图，也不会把错误页当成展厅预览图。**

### 无法访问的入口已直接删除

巡检确认打不开的 6 条入口已**从数据中删除**（不是隐藏），导航页不再出现它们，
页面也不再显示"已隐藏/失效"之类的提示。删除清单记录在 `data/dropped.json`：

| 序号 | 入口 | 原因 |
|---|---|---|
| 01 | 延安革命纪念馆 · 官网首页 | 连接超时，网络不可达 |
| 19 | 中共一大纪念馆 · 网上纪念馆（pano站） | 返回 403，服务器拒绝访问 |
| 30 | 韶山毛泽东同志纪念馆 · 网上展厅（旧版） | 返回 404，页面已不存在 |
| 36 | 南昌八一起义纪念馆 · VR全景（第三方收录） | 返回 404，页面已不存在 |
| 39 | 军博 · 建党百年主题展数字展馆 | 域名无法连接 |
| 40 | 军博 · 领航强军向复兴新时代成就展数字展馆 | 域名无法连接 |

**删除是怎么落地的**：`tools/build_data.py` 顶部的 `DROPPED` 字典列出要剔除的序号及原因，
读取源表时直接跳过这些行，并在 `data/dropped.json` 留档。因为拦截发生在数据管道的入口，
以后重跑 `build_data.py` 也不会把它们带回来。

**若某条日后恢复**：删掉 `DROPPED` 里对应的那一项，依次重跑：

```powershell
python tools/build_data.py     # 该条重新进入数据
node tools/shot-worker.mjs _build/shots.json "_build/raw,images/thumbs" 0 1   # 补预览图
python tools/build_site.py     # 重新巡检 + 生成 entries.js
```

> 源表的完整原始数据仍保留在 `E:\工程文件\workb\红色博物馆线上入口与公众号菜单配置表.xlsx`，
> 删除前的完整 JSON 也备份在 `_build/entries-before-drop.json`，不会丢数据。

`build_site.py` 每次巡检若发现**新的**失效入口，会打印提示，但不会自动删除 ——
由你确认后再把序号加进 `DROPPED`，避免误删只是临时抽风的站点。

日后这些站点恢复后，重跑一次即可补齐（已有截图会自动跳过）：

```powershell
node tools/shot-worker.mjs _build/shots.json "_build/raw,images/thumbs" 0 1
python tools/build_site.py
```

### entries.json 单条字段

| 字段 | 说明 |
|---|---|
| `id` | 稳定标识，同时是图片文件名（`e01` → `images/thumbs/e01.jpg`） |
| `seq` | 原表格序号 |
| `venue` / `region` | 馆名 / 属地 |
| `name` | 入口（展览）名称 |
| `etype` | 归一化后的入口类型 |
| `bucket` | 浏览维度（云上观展 / 走进场馆 / 学习教育） |
| `url` / `urlNote` | 访问链接 / 链接附注（如"首页入口"） |
| `linkable` | 是否可直接跳转；`false` 渲染为引导卡 |
| `https` / `risk` | 协议与风险等级：`ok` / `http` / `domain` / `guide` |
| `verified` / `verify` | 数据来源标记（官方确认 / 第三方收录）。页面只在官方来源的卡片上挂「官方确认」角标，其余不再标注，来源说明见页脚 |
| `mobile` | 移动端适配建议（原表格末列）。原表里的"需复核"不改数据、只在渲染时显示为"可正常打开"（见 app.js 的 `MOBILE_TEXT`） |
| `group` | 党史时序分组 |
| `image` | 卡片预览图路径 |
| `dead` / `health` | 巡检结果；当前全部条目 `dead=false` |
| `hasShot` | 是否采到真实截图 |

## 六、技术说明

- **零依赖前端**：单页 HTML + 原生 CSS + 原生 JS，无框架、无打包、无 CDN，
  响应体积小、兼容微信内置浏览器（含较旧的 X5 内核）
- **数据双通道**：`data/entries.js` 内联数据保证 `file://` 直接双击可用；
  通过 http(s) 打开时会再 `fetch('data/entries.json')` 覆盖，便于只改 JSON 即生效
- **预览图采集**：`puppeteer-core` 驱动**本机已安装的 Chrome**（不下载 Chromium），
  支持 `--ignore-certificate-errors` 放行 `.mil.cn` 证书问题、对防盗链站点补 Referer、
  自动点掉"进入网站"类引导浮层、对全景站点等待 WebGL canvas 渲染
- **二维码**：`assets/qr.js` 为本地实现的 QR 编码器（字节模式 / 纠错等级 L / 版本 1–8），
  不请求任何外部二维码服务；含自检（格式信息 BCH 对照规范表、RS 多项式整除不变式、
  容量与规范一致、编解码往返一致）

## 七、质量保证

- 每张预览图的原始/成品体积
- 46 个入口的 HTTP 巡检结果（状态码、失败类型）
- 判为失效的入口清单与未采集到截图的入口清单

页面上的"链接巡检"结论显示在页脚，与 QA 报告一致。
